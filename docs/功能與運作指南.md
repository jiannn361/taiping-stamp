# 雲遊太平電子護照：功能與運作指南

本指南依目前程式碼整理，供活動主辦單位、管理者與維護人員了解系統現況。實際上線內容若有後續調整，請以最新部署版本及活動公告為準。

## 1. 系統概覽

本系統是一個以 LINE 身分登入的手機網頁，分為「遊客端」與「店家端」。遊客展示專屬 QR Code 或 8 碼代碼，由合作店家依單筆消費金額發送點數。遊客可查看點數、活動規則與合作店家；獎項核銷功能已有程式流程，但目前沒有設定任何可兌換獎項。

主要流程：

1. 使用者開啟活動網頁，完成 LINE LIFF 登入。
2. 系統取得 LINE 個人資料，依 LINE User ID 是否列於店家授權名單，顯示遊客端或店家端。
3. 店家掃描遊客 QR Code，或輸入遊客的 8 碼代碼，填寫本次結帳金額。
4. 系統按店家固定類別換算點數；店家確認後送至點數 API，再由後端轉交 Google Apps Script（GAS）處理。
5. 遊客端定期重新查詢點數並顯示結果。

## 2. 登入、角色與資料來源

### LINE 登入與角色

- 網頁載入後初始化 LIFF；尚未登入者會進入 LINE 登入流程。初始化或取得資料失敗時，顯示「請在 LINE 應用程式中開啟此活動網頁！」及重新整理按鈕。這是畫面上的通用錯誤提示，不一定代表唯一原因就是開啟方式。
- 頁首顯示 LINE 頭像、名稱，以及「遊客端」或「店家端」。沒有自行切換角色的按鈕。
- 店家授權名單 `SHOP_ADMINS` 寫在前端程式內，以完整 LINE User ID 對應店家代號、店名及發點類別。未列入者會進入遊客端；新增或變更權限需要管理者更新程式並重新部署，不是送出申請後自動開通。
- 店家端顯示的發點類別由名單固定指定，店家無法自行切換。

### 點數與店家名單

- 遊客端使用 LINE User ID 最後 8 碼（轉成大寫）作為顯示與查詢用代碼。QR Code 則包含完整 LINE User ID 與 LINE 顯示名稱，格式為 `完整UserID|顯示名稱`。
- `/api/points` 接收查詢或發／扣點要求，轉交 GAS。GET 須帶 `uid`；POST 轉送請求內容。GAS 回傳錯誤時，API 依情況回傳錯誤狀態；密碼相關錯誤回傳 401。
- `/api/shops` 向 GAS 讀取合作店家資料。成功回應設有約 1 小時的共享快取，並允許過期資料於重新驗證期間暫時顯示。因此後台店家資料更新未必立即出現在前端。
- 程式庫只含前端與兩個 API 轉接程式；GAS 與試算表的內部欄位、權限及實際寫入規則不在此程式庫，不能單憑前端推定其完整行為。

## 3. 遊客端功能

### 電子護照與集點顯示

- 首頁顯示目前總點數、雲朵集點格、兩種類別色標、專屬 QR Code 與 8 碼代碼。
- 小吃／伴手禮以藍綠色標示；餐廳／住宿以金黃色標示。每 10 格擴增一排，最少顯示 10 格。
- 點數資料於畫面載入時查詢，之後每 15 秒重新查詢一次。網路錯誤時本次查詢不更新，畫面可能暫時保留舊值。
- 顯示總點數時，優先把兩大類別加總；若加總為 0，才使用後端提供的 `total`。餐廳／住宿優先讀取合併欄位 `restaurant_stay`，否則讀取 `restaurant`。舊資料欄位的相容處理應與 GAS 實際格式一起確認。
- QR 圖片由外部 QR 圖片服務產生；其編碼內容包含完整 LINE User ID 及顯示名稱。分享或截圖時應把它視為個人識別資訊，不要公開張貼。

### 活動規則與兌換紀錄

- 「紀錄與規則」顯示程式內固定寫入的活動期間：民國 115 年 10 月 9 日至 10 月 11 日，以及小吃／伴手禮單筆滿 NT$200 贈 1 點、餐廳／住宿單筆滿 NT$400 贈 1 點等說明。
- 「我的兌換紀錄」只記錄本次頁面開啟期間在此畫面成功核銷的項目、時間與序號；重新開啟後不會從後端載入歷史紀錄。它不是完整交易明細。

### 合作店家

- 「合作店家」有地圖與列表兩種模式，首次切入時讀取店家名單。地圖以 OpenStreetMap 圖磚顯示有經緯度的店家標記，點選可看詳情。
- 列表需先選「小吃／伴手禮」或「餐廳／住宿」才顯示店家。每次處理列表時，同類店家會隨機排序；不是依距離或名稱排序。
- 店家詳情可顯示店名、服務標籤、地址及介紹；「導航」使用店家提供的地圖連結，否則以經緯度開啟 Google Maps；有電話時顯示撥號按鈕。實際欄位取決於店家資料是否提供。
- 類別文字會辨識中文及部分英文關鍵字；未辨識到的類別在前端預設為「小吃／伴手禮」。資料建檔時應檢查分類，避免錯誤歸類。

### 店家權限申請入口

- 遊客端底部「我是合作店家，需要開通發點權限」可輸入店名、查看完整 LINE User ID，並嘗試以 LINE 傳送預填文字。
- 此操作只建立待傳送訊息，不會自動修改授權名單，也不保證傳到指定群組。申請者應確認收件對象與訊息確實送出；主辦單位仍須審核、設定類別、加入授權名單並部署更新。

## 4. 店家端功能與計算規則

- 授權店家進入發點專員介面後，先看到店名、固定類別與門檻：小吃／伴手禮每滿 NT$200 為 1 點；餐廳／住宿每滿 NT$400 為 1 點。
- 發點點數為 `單筆結帳金額 ÷ 所屬類別門檻` 後無條件捨去。例如小吃類 NT$450 為 2 點，餐廳類 NT$799 為 1 點。不足 1 點時不能進入確認步驟。金額按畫面輸入的整數計算；程式沒有跨筆累計功能。
- 可使用手機後鏡頭掃描遊客 QR Code，讀取完整 User ID 與名稱；或手動輸入遊客畫面上的 8 碼代碼並查詢。手動查詢失敗時，畫面仍可能以「手動輸入新遊客」或「無網路(手動鎖定)」進入下一步；這不代表該代碼已驗證，也不代表可離線發點。
- 鎖定遊客後以數字鍵盤輸入結帳總金額，查看換算點數，再進入確認頁。單筆達 10 點時會額外顯示防呆警告，但沒有硬性上限。
- 確認送出後，頁面防止連點；對同一遊客在此店家裝置的瀏覽器儲存 1 分鐘冷卻時間。這是前端的防重複機制，並非可跨裝置保證的全域交易防重複機制。
- 成功後顯示最近 5 筆發送紀錄，僅保存在本次頁面狀態；重新整理後不會顯示。若傳送狀態未明，程式會提示先確認遊客點數並保留冷卻，以免再次發點。

## 5. 兌換與特殊核銷的現況

- 「獎項兌換」分頁目前可見，但獎項清單 `redeemGifts` 為空，畫面只顯示「兌換品項準備中」。因此一般遊客目前無可選獎品，無法走一般獎項核銷流程。
- 程式已有獎項扣點流程：有足夠點數時選獎項，由服務台工作人員在遊客畫面輸入密碼，確認後向 `/api/points` 送出 `deduct`、獎品名稱與核銷序號。實際能否成功，仍取決於 GAS 的檢查與資料狀態。獎項、點數與兌換辦法須由主辦單位先確認並設定。
- 「服務台專用特殊核銷／紙本合併兌換」流程也已寫入程式，可輸入扣除點數，但開關 `SHOW_CUSTOM_REDEMPTION` 目前為關閉，一般畫面沒有入口。不要將它寫成現場已開放服務。
- 工作人員密碼在目前前端也有檢查，且會送至後端；前端檢查不能作為唯一的權限保護。正式啟用核銷前，應確認 GAS 端驗證、密碼管理與操作權限。

## 6. 開通、維護與注意事項

1. 主辦單位先確認店家名稱、完整 LINE User ID、店家代號與發點類別，再更新前端授權名單及部署；申請畫面不是自動審核系統。
2. 確認 GAS 的點數資料、店家資料及兩個 API 可正常讀寫。前端沒有管理後台可直接修改點數、活動規則、獎項或店家資訊。
3. 活動日期、門檻、獎項開關等目前寫在程式內。更改活動辦法時，需同步修改程式顯示與後端規則，避免現場說明與實際計算不同。
4. 頁面仰賴 LINE LIFF、外部 QR 圖片服務、地圖圖磚與前端函式庫；相機掃描需鏡頭權限及可用的裝置／瀏覽器。網路或第三方服務異常時，功能可能受影響。
5. `manifest.json` 宣告了 192 與 512 像素圖示，但目前程式庫只見 `icon-192.png`；若要完整支援安裝到主畫面，應補齊並驗證 512 像素圖示。
6. 發點或扣點若出現逾時、錯誤或畫面與後端不一致，先查核後端交易與遊客最新點數，再決定是否補救；不要只憑本次畫面的暫存紀錄重送交易。

本指南描述的是此版本程式「可看到的介面與送出的資料」，並未聲稱已驗證正式環境的 GAS 寫入、獎品庫存或實際 LINE 群組傳送結果。
